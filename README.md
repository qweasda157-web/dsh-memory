# dsh-memory

给 DSH 里的 Agent 一份**跨天的记忆**。

模型本身没有持久的记忆：会话一结束，昨天发生过什么就不存在了。这个插件把「它经历过的事」按天写进磁盘，下次启动时自动把最近几天带回上下文，也支持按日期回查任意一天。

一句话：**不是把聊天记录存下来，而是让它记得"那天我干了什么"。**

- 零第三方依赖（只用 Node 内置模块和 `Intl`）
- 数据是普通 JSON + Markdown 文件，随时可以看、可以改、可以备份
- 只写在自己配置的目录里，不越界

## 一、它解决什么问题

普通的对话历史有两个硬伤：

1. **跨不过会话**。开一个新对话，昨天说的话就没了。
2. **跨不过上下文窗口**。聊久了会被压缩/截断，细节丢失。

这个插件走的是另一条路：**在事情发生之后，主动写一条"记忆"**。写入的是自然语言的、第一人称的记录，比如

> - 20:15 我在首页推荐看到了《为什么猫会盯着墙角看》（UP主A），三分半，讲猫的听觉频段。
> - 20:46 我在评论区看到了有人在我的评论下面回了一句。我没有回他。

下次启动时，最近三天会自动带进上下文。这些文字**不会被上下文压缩影响**，因为它们每次都是从磁盘重新读出来的。

### 它不做什么

- **不是聊天记录**。它记的是"发生了什么"，不是逐字对话。
- **不会自动判断"什么值得记"**。什么时候写、写什么，由模型（或你）决定。
- **不是 RAG**。没有向量检索，就是按日期取，简单直接。

## 二、快速开始

不需要 `npm install`，也不需要构建。有 Node.js 18+ 即可。

```bash
# 看一个完整例子（会在 examples/.demo/ 里建一个临时库，跑完自动删掉）
node examples/demo.mjs

# 想留着看文件的话
node examples/demo.mjs --keep
```

输出会依次展示：写入三天的日记 → 按日期读回其中一天 → 启动时注入的样子 → 目录结构。

## 三、数据长什么样

```
<root>/.memory/
└─ diary/
   ├─ index.json                    机器索引：哪天有几条、什么时候改的
   └─ days/
      ├─ 2026-11-03.json            结构化真源
      ├─ 2026-11-03.md              同一份内容的 Markdown 版本
      └─ …
```

**JSON 是真源，Markdown 是渲染产物。** 改 JSON 之后重新渲染，反过来不成立。

### `.md`（人读 / 模型读的版本）

```markdown
## 2026-11-03（周二）

那天大概是这样：今天看了一个讲猫为什么会盯着墙角的视频，在底下留了条评论。

- 20:15 我在首页推荐看到了《为什么猫会盯着墙角看》（UP主A），三分半，讲猫的听觉频段。
- 20:30 我在《为什么猫会盯着墙角看》的评论区看到了关于"猫能听见墙里的老鼠"的争论。
- 20:46 我在评论区看到了有人在我的评论下面回了一句。我没有回他。
```

### `.json`（机器读的版本）

一条记忆（episode）长这样：

```json
{
  "id": "20261103-201502-a1b2",
  "at": "2026-11-03T20:15:02+08:00",
  "day": "2026-11-03",
  "saw": [
    {
      "what": "《为什么猫会盯着墙角看》",
      "where": "首页推荐",
      "author": "UP主A",
      "link": "https://www.bilibili.com/video/BV1xx411c7mD",
      "notes": "三分半，讲猫的听觉频段"
    }
  ],
  "actions": [
    { "kind": "观看", "target": "《为什么猫会盯着墙角看》", "detail": "看到 2:10" },
    { "kind": "点赞", "target": "《为什么猫会盯着墙角看》" }
  ],
  "felt": "这视频讲得挺认真",
  "tags": []
}
```

字段说明：

| 字段 | 含义 |
|---|---|
| `time` / `at` | 发生时间。`"HH:mm"` 即可（自动补当天），跨天要写完整日期 |
| `saw` | 看到了什么（`what` 内容、`where` 场景、`author` 作者、`link` 链接、`notes` 补充） |
| `left` | 留下了什么。`what` 是东西，`notes` 是**动作**（"没有回他"） |
| `actions` | 做了什么（`kind` 种类、`target` 对象、`detail` 正文） |
| `responses` | 世界怎么回应（有人回复、点赞、限流迹象等） |
| `felt` | 当时怎么想的（可选，不必勉强） |
| `notes` | 补充说明 |
| `tags` | 自由标签 |

同一 `id` 重复写入**是更新不是追加**，方便修正。

## 四、对外暴露的东西

### 1. 系统提示注入

启动时把最近 N 天（默认 3 天）的日记拼进系统提示，标题是「我的记事」：

```
# 我的记事（自动带过来的）

这是你之前几天的记事，一上来就带着，不用重新想一遍。

（这是你自己这几天的记事。下面最后一天的末尾就是"现在"，接着过就好 —— 不用复述，也不用谢。）

## 2026-11-02（周一）
...
## 2026-11-03（周二）
...
```

注入的正文**每轮重新计算**，所以跨天的长会话会自动滚动到新的"最近三天"，不会卡在旧内容上。

**没有记录的日子也会保留**，显示为「这天没有留下什么记录」——因为"昨天没记"本身也是信息。

正文有 12000 字符的硬上限，超了从最早那天开始丢。

### 2. `diary` 工具

模型可以自己调用，两个用途：

```js
// 回看某一天
diary({ day: "2026-11-03" })

// 记下刚才发生的事
diary({
  entries: [
    { time: "20:15", saw: [{ what: "《某视频》", where: "首页推荐" }] }
  ],
  overview: "今天主要在刷首页推荐"
})
```

`day` 接受 `YYYY-MM-DD`，也接受 `today` / `昨天` / `前天`。

## 五、命令行

不装进 DSH 也能用：

```bash
node bin/remember.mjs help

node bin/remember.mjs bootstrap --days 3        # 打印启动注入的正文
node bin/remember.mjs recall --day 2026-11-03   # 打印某天
node bin/remember.mjs recall --last 3           # 打印最近三天
node bin/remember.mjs note --file 条目.json     # 写入条目
node bin/remember.mjs render --day 2026-11-03   # 按 json 重画 .md
node bin/remember.mjs days                      # 列出有哪些日子
```

公共参数：`--root <工作区>`、`--dir .memory`、`--tz Asia/Shanghai`、`--today 2026-11-03`、`--json`。

`--today` 用来覆盖"今天"的判断，方便复现某天的状态。

## 六、配置项

写在插件的配置里（`cordis.patch.yml` 或宿主等价位置）：

```yaml
- id: memory
  name: dsh-memory
  config:
    root: 'C:/path/to/workspace'   # 记忆库根目录；空 = 用 process.cwd()
    dir: .memory                   # 库目录（必须在 root 内）
    tz: Asia/Shanghai              # 时区；空 = 系统本地时区
    bootstrapDays: 3               # 启动注入几天（1–30）
    enabled: true                  # 总开关
    order: 900                     # 在系统提示里的排序位
    timeoutMs: 20000               # 单次工具调用超时
```

**非法配置不会抛错**，一律回落到默认值并通过 `logger.warn` 记一条问题——记忆是纯增益功能，不该因为配错就把宿主搞崩。

> 旧版本有个 `manifest` 配置项（记录防篡改痕迹），现已移除；如果配置里还留着会被忽略并提示一声。

## 八、装进 DSH

DSH 的插件是 Cordis 插件。这个包导出 `name` / `inject` / `apply(ctx, config)`，符合要求。

装法（在 profile 的 `package.json` 里加依赖 + 进 `dsh.profile.bundles`）：

```json
{
  "dependencies": {
    "dsh-memory": "link:C:/path/to/dsh-memory"
  },
  "dsh": {
    "profile": {
      "bundles": ["@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app", "dsh-memory"]
    }
  }
}
```

然后重启 DSH，在插件页应该能看到它，并处于「运行中」。

### 关于宿主 API 的几点

这些是实际接线时踩过的坑，记下来省得重踩：

| 事项 | 做法 |
|---|---|
| 系统提示注入 | `ctx.get('systemPrompt').section({ name, order, interpolate: false, text: () => 字符串 })`，`text` 必须返回**字符串** |
| 服务获取 | 用 `ctx.get('服务名')` + try/catch 探测，**不要**写进硬 `inject`（精简宿主上会整个 apply 失败） |
| 工作区路径 | **不存在 `ctx.workspaceDir`**。用配置显式给 `root`，缺省退回 `process.cwd()` |
| 受限代理 | 读未声明的属性会**抛错**，所以探测本身也要包在 try 里 |

### 和上下文压缩的关系

DSH 的自动压缩会把较早的对话压成摘要。这个插件注入的记事位于**系统提示**中，而压缩的范围永远从第一个非 system 节点开始——系统提示不会被压掉。

也就是说：**对话聊久了细节会被压缩，但记事里的东西每次都是从磁盘重新读的，不受影响。**
